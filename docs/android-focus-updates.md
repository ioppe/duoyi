# Android 专注与应用更新

本页约定 Android 严格专注、运行通知与更新下载的行为。通知沿用多仪当前主题的强调色和品牌文案；系统通知面板负责字体、背景和深浅色适配。固定应用标志仍使用 `ic_stat_duoyi`，不随主题替换应用 Logo。

## 版本与更新判断

`versionName` 是语义版本，`versionCode` 是 APK 的真实构建编号，两者不能互相换算。GitHub 的发布标签只证明版本名，不能据此编造构建编号。没有可信 build 时使用语义版本比较；同版本重建只有在取得真实、更高的 build 后才提示更新。较旧语义版本不能凭更大的 build 触发降级更新或强制更新。

| 响应字段 | 类型与来源约定 |
| --- | --- |
| `latest_version_code` | 真实 build 或 `null`；GitHub 只有标签时为 `null`。兼容数值只有来源可信时才能参与比较。 |
| `latest_version_code_source` | `manifest` 为本地产物元数据，`configured` 为明确的 build 配置；`derived` 为保留的旧推算值，`unknown` 为未知。 |
| `minimum_supported_version_code` | 最低支持版本对应的 build；兼容响应可能保留旧推算数值，必须结合来源判断，不能复用不同版本名的最新版 build。 |
| `minimum_supported_version_code_source` | 与最新版使用相同来源枚举；`derived` / `unknown` 不触发同版本 build 强更。 |

没有来源字段的旧服务器按历史兼容规则读取：恰好等于旧公式的 build 视为未知；不能用 `0` 或另一个推算值冒充真实 build。后端自己的打包编号不证明 GitHub APK 的编号。

旧服务器曾把版本名按 `major × 100000 + minor × 10000 + patch` 推算成 build。例如 `2.0.0` 被错误下发为 `200000`，会使实际已安装 `2.0.0 / 142023` 的客户端持续提示更新。客户端须兼容这一历史数据；相同规则也适用于最低支持版本、GitHub 回退及已下载缓存。后端应从明确的本地产物元数据或管理员配置取得真实构建编号，并说明来源；未知值保持未知。

## 严格专注

- 分心应用选择器显示应用原生图标、名称及包名，支持自适应图标。缺失或无法解码的图标使用占位图，不影响勾选。应用内容独立滚动，底部“取消 / 完成”保持可见，长名单无需滚到末尾才能保存。黑名单、白名单、搜索、草稿取消和点击完成后保存的规则保持一致。
- 授权状态应在打开设置面板、返回应用时重新读取。Android 的组件短名（`包名/.服务类名`）与完整类名须等价识别；前台应用轮询不能覆盖无障碍授权字段。
- 使用情况访问与无障碍是独立能力：前者读取前台应用，后者负责已配置应用的拦截。系统已启用并连接多仪无障碍服务时，严格专注运行期间打开分心应用应返回多仪专注页。
- 拦截失败应留有可诊断日志，不进行无界重试。拦截配置有会话期限；暂停、结束、重置和释放会话后停止拦截，不能因残留偏好永久拦截其他应用。
- 无障碍快速拉回应用后，记录仍应保留真实分心应用事件。惩罚记录显示应用名称，并保留包名；旧记录缺失名称时回退包名，既有备份和云同步 JSON 仍可读取。

## 专注运行通知

通知使用 Android 标准模板，左侧为应用标志，标题显示当前专注或休息阶段，任务名称为正文，系统计时器显示剩余或已用时间，进度条显示倒计时阶段进度。点击整条通知返回专注页。

```text
应用标志  当前阶段                    剩余时间
          关联任务（没有任务时显示专注文案）
          ━━━━━━━━━━━░░░░░░░░░░░░░░░
          整条通知可点击返回专注
```

- 独立计时前台服务使用 `specialUse` 类型，与白噪音播放服务分开；不需要开启白噪音才能显示计时。
- 使用系统 chronometer 计时，避免依赖后台 Dart 每秒重绘。开始、暂停、继续、模式切换、主题和语言变化同步通知；暂停冻结时间，结束和重置清理通知，倒计时到期不显示负值。
- 通知低优先级、静音、只首次提醒，使用当前主题 primary 作为强调色；不向普通提醒历史写入每秒状态。通知权限被拒绝时，应用内计时仍可使用。

## APK 后台下载

用户点击下载后交由 Android `DownloadManager` 执行。离开应用或关闭更新弹窗不取消系统下载，进度由通知栏持续显示。系统可按网络条件排队、暂停或重试；未知总大小显示不确定进度，不能伪造百分比。

应用保存自己创建的下载 ID、版本及资源信息，重入后恢复运行状态；只能查询、取消或安装本应用持有的任务。下载失败显示错误并允许重试。更新弹窗中的长安装包名应自然换行，窄屏和大字体下仍能看到内容并操作底部按钮。下载完成后提供点击安装入口，仍遵循系统未知来源授权和安装确认流程，不能在后台自行弹出安装器。

使用应用专属目录和既有 FileProvider 安装流程，不申请广泛存储权限。系统下载进度通知采用平台样式；应用的完成通知使用当前主题强调色、固定应用标志和对应语言文案。

## 验证边界

单元测试应覆盖历史推算 build、同版本真实新 build、旧版本防降级、授权字段保留、图标与旧记录兼容、原生事件去重、拦截期限以及通知与下载生命周期。真机须验证授权设置返回、实际拉回、通知倒计时、后台下载与安装入口。构建成功或静态测试通过不能替代这些实际交互。

本地验证保留正式应用及其数据。签名或版本不兼容时使用独立验证应用，证据中记录源代码、APK 校验值、设备与实际执行范围。参见 [本地 Android 快速验证](android-local-testing.md) 与 [手动回归清单](manual-regression-checklist.md)。
