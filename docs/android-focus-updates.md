# Android 专注与应用更新

本页约定 Android 严格专注、运行通知与更新下载的行为。通知沿用多仪当前主题的强调色和品牌文案；系统通知面板负责字体、背景和深浅色适配。固定应用标志仍使用 `ic_stat_duoyi`，不随主题替换应用 Logo。

## 版本与更新判断

`versionName` 是语义版本，`versionCode` 是 APK 的真实构建编号，两者不能互相换算。GitHub 的发布标签只证明版本名，不能据此编造构建编号。没有可信 build 时使用语义版本比较；同版本重建只有在取得真实、更高的 build 后才提示更新。较旧语义版本不能凭更大的 build 触发降级更新或强制更新。

| 响应字段 | 类型与来源约定 |
| --- | --- |
| `latest_version_code` | 真实 build 或 `null`；GitHub 只有标签时为 `null`。兼容数值只有来源可信时才能参与比较。 |
| `latest_version_code_source` | `manifest` 为本地产物元数据，`configured` 为明确的 build 配置；`derived` 为保留的旧推算值，`unknown` 为未知。 |
| `minimum_supported_version_code` | 最低支持版本对应的 build；兼容响应可能保留旧推算数值，必须结合来源判断，不能复用不同版本名的最新版 build。 |
| `minimum_supported_version_code_source` | 与最新版使用相同来源枚举；`derived` / `unknown` 不触发同版本 build 强更。 |

没有来源字段的旧服务器按历史兼容规则读取：恰好等于旧公式的 build 视为未知；不能用 `0` 或另一个推算值冒充真实 build。后端自己的打包编号不证明 GitHub APK 的编号。

旧服务器曾把版本名按 `major × 100000 + minor × 10000 + patch` 推算成 build。例如 `2.0.0` 被错误下发为 `200000`，会使实际已安装 `2.0.0 / 142023` 的客户端持续提示更新。客户端须兼容这一历史数据；相同规则也适用于最低支持版本、GitHub 回退及已下载缓存。后端应从明确的本地产物元数据或管理员配置取得真实构建编号，并说明来源；未知值保持未知。

## 严格专注

- 分心应用选择器显示应用原生图标、名称及包名，支持自适应图标。缺失或无法解码的图标使用占位图，不影响勾选。应用内容独立滚动，底部“取消 / 完成”保持可见，长名单无需滚到末尾才能保存。黑名单、白名单、搜索、草稿取消和点击完成后保存的规则保持一致。
- 授权状态应在打开设置面板、返回应用时重新读取。Android 的组件短名（`包名/.服务类名`）与完整类名须等价识别；前台应用轮询不能覆盖无障碍授权字段。
- 使用情况访问与无障碍是独立能力：无障碍窗口事件负责快速检测，已授权的使用情况访问读取近期应用前后台切换元数据，补充未发送窗口事件的应用。严格专注要求系统已启用并连接多仪无障碍服务、且允许本应用从后台显示。小米、Redmi、POCO 还需在系统应用信息 → 权限管理 → 其他权限中允许“后台弹出界面”；辅助功能已启用不代表该项已允许。部分应用（本次小米上的支付宝登录页）未投递窗口事件，还需用户另行授权使用情况访问以补充检测；它不能代替无障碍连接或后台显示许可。面板须明确提示，不伪造授权状态或绕过系统许可。
- 小米等厂商的省电策略还可能冻结整个应用进程，即使辅助功能显示已连接、计时前台服务仍在，回调和计时刷新也会停止。出现此情况时，须由用户在该应用的系统“省电策略 / 电量管理”中选择“无限制”，并知悉后台耗电可能增加；后台弹出许可、使用情况访问和省电策略是不同条件，不能相互替代。应用不得自动修改省电策略、解冻内核 cgroup 或伪称设置成功。排查须区分 ActivityManager 标志与实际内核冻结状态，并以设置后的真实重复启动、暂停/继续结果验证。
- 使用情况补漏仅在有效严格专注配置期间执行，约每 500ms 在工作线程查询一次当前监控起点后、最近 5 秒的 `UsageEvents`，只读取包名、类型与时间；未授权、锁屏、息屏或查询失败时不猜测前台，不读取界面内容。配置变化、暂停、结束、重置、租约到期与服务销毁使在途结果失效，并停止不再需要的监控；迟到结果不能恢复旧会话。
- 恢复前台重复同步完全相同的启停值、包集合和到期时间时，原生存储不重发配置变更；不能因此取消正在验证的返回或移动使用情况监控起点。真实配置变化仍须作废旧工作。
- Flutter 通道的状态/前台记录查询在独立工作线程读取系统快照，不得同步阻塞负责无障碍回调、计时通知与暂停/继续命令的主线程；同时最多一次系统查询，等待者有界合并，销毁时结束等待并丢弃迟到结果。该记录快照仍不得作为强制拉回依据。
- 白名单表示“允许”，不是“默认”：原生拦截集合由客户端下发（白名单模式下是其补集，原生侧不做二次判定）。用户切到微信、QQ 等允许应用或本应用时，待执行的拉回必须立即取消，不能把人从允许的应用里拉走。使用情况读取中的旧包暂停事件不能清除已切到新包的观察；明确的当前包离开事件会取消待执行返回，并保留时刻以拒绝旧事件复活。
- “已请求返回”与“确认返回”是两件事。`startActivity` 成功只说明显式 `duoyi://tab/focus` 深链交给了系统，日志只记 `requested`；只有观察到本应用真的成为前台（API 29+ 的 `onTopResumedActivityChanged`、更低版本 `onResume`，或收到本包窗口/近期前台切换事件）才记为确认返回，并清空待验证状态。请求成功不能当作“已拉回”的证据。
- 窗口事件触发的拉回约 600ms 验证，仍停在同一被拦截应用时最多补发一次（首次 + 一次重试）；使用情况补漏每个新的前台切换事件只请求一次，仍检查确认但不依据旧快照补发。未确认记 `unconfirmed`。未确认只结束**本轮验证**，保留由真实窗口重复事件排队的 1.5s 复查；确认返回、切到允许应用、配置停用/过期或服务销毁则整体取消返回工作，并记录触发窗口与原因。所有请求前重新检查配置与设备解锁状态。
- 冷却 1.5s **全局**生效：被拒事件不推进冷却、不改写已接受包名。窗口事件只排队一次固定截止时刻的复查，当前前台仍是目标且仍在拦截期才再请求，复查不自行排下一轮。使用情况补漏在冷却内不依据缓存包排队返回，也不消费该事件；后续监控必须重新查询，当前仍是最新分心前台且冷却已结束才接受。相同使用情况事件不能反复请求或重复记惩罚。
- 前台观察统一使用 `SystemClock.uptimeMillis`；窗口事件直接使用同基准的 `AccessibilityEvent.eventTime`，使用情况事件按同次捕获的墙钟/uptime 及真实事件年龄换算，不能把旧事件时间刷新为当前时间。更旧的观察不得覆盖更新的前台确认；未来或超出 5 秒窗口的使用情况事件不作为拉回依据。
- 无障碍快速拉回应用后，记录仍应保留真实分心应用事件。惩罚记录显示应用名称，并保留包名；旧记录缺失名称时回退包名，既有备份和云同步 JSON 仍可读取。
- 专注拉回、计时通知和小组件的 URI 由原生 `duoyi/deep_links` 通道统一分发，冷启动仍通过既有初始链接队列接收；OAuth 与文本分享保持原通道。`MainActivity` 显式关闭 Flutter 默认深链接命名路由分发，避免同一 URI 被重复送入未注册的路由而触发异常。

## 专注运行通知

通知使用 Android 标准模板，左侧为应用标志，标题显示当前专注或休息阶段，**正文第一行是剩余/已计时时间**（如 `剩余 24:53`、`已计时 01:23`），暂停时为 `剩余 24:53 · 已暂停`。`BigTextStyle` 展开详情同样保留时间首行，第二行显示关联任务全名或“无关联任务”兜底；系统 chronometer 与进度条仍作为附加展示。点击整条通知返回专注页。

```text
应用标志  当前阶段                    暂停 | 重置
          剩余 24:53
          ━━━━━━━━━━━░░░░░░░░░░░░░░░
          （展开后保留时间，并显示任务全名）
```

- 独立计时前台服务使用 `specialUse` 类型，与白噪音播放服务分开；不需要开启白噪音才能显示计时。
- 服务在 `onCreate` 即完成最小前台提升，再按计时载荷更新内容；停止通知直接使用 `stopService`，不能通过创建一个 STOP 服务实例来停止。冷启动恢复中的连续停止/同步请求也必须满足 Android 前台服务时限，避免 `ForegroundServiceDidNotStartInTimeException`。
- 正文时间由前台服务每 1 秒按 `SystemClock.elapsedRealtime` 推进（倒计时与正计时一致），不额外依赖 Dart 秒级同步，也不申请 wakelock。倒计时秒数向上取整（1001ms 仍显示 `00:02`），正计时向下取整，超过 1 小时显示 `h:mm:ss`。
- 运行态提供“暂停 / 重置”，暂停态提供“开始 / 重置”；开始延续原相位、任务与剩余时间，重置复用既有 reset 语义（回满时长、不产生完成记录）。按钮是标准 `NotificationCompat` actions，点击回到专注页并立即回调既有 `applyWidgetControl`，由 session + revision + state 校验；无有效绑定（旧 payload）时不显示按钮，旧/重复点击不改状态也不重复记惩罚。
- 共享专注模式下，通知和组件按钮按会话、版本与状态校验后转换为显式命令；应用收到服务端确认快照后更新显示，不在本地暂停、结算或重复记控制处罚。应用未运行时，已保存共享模式的组件按钮经 HTTP 先读取权威快照，仅在绑定有效时提交命令，不常驻计时器或 WS；网络失败保留共享模式，过期绑定只刷新投影。访客和明确不支持此能力的旧后端沿用本地控制。实时传播仅保证在线进程，系统挂起或退出后依靠恢复快照收敛，见 [同账号多端专注](focus-runtime-sync.md)。
- Dart 同步时带 canonical 锚点：倒计时为 Provider 的结束时刻，正计时为开始时刻，暂停为 0。原生首次收到按锚点与当前时刻折算显示值，之后只用单调时钟推进；到期时刻只由该锚点决定，秒级刷新与主题/语言重推都不会延长期限。旧 payload 无锚点时退回相对剩余值。
- 通知低优先级、静音、只首次提醒，使用当前主题 primary 作为强调色；不向普通提醒历史写入每秒状态。通知权限被拒绝时，应用内计时仍可使用。

## APK 后台下载

用户点击下载后交由 Android `DownloadManager` 执行。离开应用或关闭更新弹窗不取消系统下载，进度由通知栏持续显示。系统可按网络条件排队、暂停或重试；未知总大小显示不确定进度，不能伪造百分比。

应用保存自己创建的下载 ID、版本及资源信息，重入后恢复运行状态；只能查询、取消或安装本应用持有的任务。下载失败显示错误并允许重试。更新弹窗中的长安装包名应自然换行，窄屏和大字体下仍能看到内容并操作底部按钮。下载完成后提供点击安装入口，仍遵循系统未知来源授权和安装确认流程，不能在后台自行弹出安装器。

使用应用专属目录和既有 FileProvider 安装流程，不申请广泛存储权限。系统下载进度通知采用平台样式；应用的完成通知使用当前主题强调色、固定应用标志和对应语言文案。

## 验证边界

单元测试应覆盖历史推算 build、同版本真实新 build、旧版本防降级、授权字段保留、图标与旧记录兼容、原生事件去重、拦截期限以及通知与下载生命周期。真机须验证授权设置返回、实际拉回、通知倒计时、后台下载与安装入口。构建成功或静态测试通过不能替代这些实际交互。

本地验证保留正式应用及其数据。签名或版本不兼容时使用独立验证应用，证据中记录源代码、APK 校验值、设备与实际执行范围。参见 [本地 Android 快速验证](android-local-testing.md) 与 [手动回归清单](manual-regression-checklist.md)。
