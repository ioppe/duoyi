# 清单类型收纳选择器

任务创建表单原先把全部清单放在同一条横向 chip 列表中。清单增加后，用户必须反复左右滑动才能找到目标，而且自定义清单的长按管理入口不易发现。首页、待办页及四象限共用的新建表单现统一使用 `TodoListGroupPicker`。

## 交互与视觉

- 默认收起为一行：清单图标、当前名称、展开箭头。未选择时显示“未分类”。选择完成或新建成功后自动收起。
- 展开后在原表单内显示一个“搜索或新建清单”输入框和有高度上限的纵向浏览区。展开及返回浏览时自动将面板带入外层表单可视区。
- 内置清单用紧凑网格，窄屏两列、较宽面板三列；自定义及历史清单名用纵向列表。可见滚动条提示列表可滚动，列表按需构建，不随清单数量无限拉长。
- 搜索依次匹配完整名称、前缀、包含关系。空查询展示分组；输入期间不创建记录。回车优先选择完全同名项或唯一匹配的已有清单；多个部分匹配时需点选已有项或新建项；没有匹配且有创建权限时可回车创建。无创建权限时只提供搜索，无结果显示“没有匹配的清单”。
- 每个可管理的自定义清单右侧都有可见的“更多”菜单，提供重命名、删除。内置清单没有管理菜单；历史任务中的名称若没有清单注册记录，只提供选择。
- 不另设加号入口或新建输入状态。没有完全同名项时，结果末尾显示“新建‘输入名称’”；点击后直接创建、选中并收起。部分匹配的已有项仍可直接选择；完全同名（去首尾空白、不区分大小写）时隐藏新建选项，复用已有项。名称长度或保存错误显示在同一搜索框下方。重命名继续由“更多”菜单进入同面板的内联字段。
- 选择“未分类”可清空当前清单。管理动作不会创建、保存或丢弃整个任务草稿。

沿用已有 `ResourceHanRounded` 粗体、主题颜色和 `DesignTokens`。设计基准是浅灰页面（#F5F6F8）、白色表面（#FFFFFF）、深色正文（#242C38）、次级灰（#78808B）与品牌红（#B84F54）；实际组件继承当前主题的 ColorScheme。选中行使用低透明度主题色背景、主题色文字和勾选反馈。控件在 320px 窄屏、放大文字和键盘弹出时仍通过外层表单滚动访问。

收起摘要的清单名称与任务名、子任务输入统一为 `DesignTokens.fontSizeMd`（16px）、1.5 行高，继承资源圆体粗字。框体保留 56px 最小高度；搜索和结果项仍使用原有紧凑层级。字号调整的实际对比见 [截图与验证](../evidence/screenshots/list-group-picker/typography/README.md)。

## 数据与权限

本次仅替换 UI，复用现有 `ListGroupProvider`、`list_groups` 同步集合和后端契约，不新增接口或数据库字段。载荷、合并与备份规则见 [同步契约：自定义清单](cloud-sync-v2-contract.md#自定义清单list_groups--post-apisync)。

可选名称仍来自内置模板、自定义注册记录、历史任务名称的规范化去重并集；共享空间的只读清单不进入选择和 AI 白名单。新建保留私有空间权限检查，管理操作执行前重新检查记录存在性与当前编辑权限。

picker 状态由服务器、账号、provider 实例和账号数据代际隔离；切换身份时旧清单编辑器销毁，异步操作仍校验开始时的身份，避免旧草稿落入新账号。

重命名保留清单 ID，删除保留同步 tombstone。沿用原有兼容规则：管理清单注册记录不会批量改写历史任务名称；历史任务仍引用的名称可能继续作为历史选项出现。保存新任务继续携带 `listGroupName` 与自定义 `listGroupId`。
