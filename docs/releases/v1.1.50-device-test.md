# v1.1.50 安卓实机测试包

版本 `1.1.50+140016`，构建分支 `fix/android-input-settings-device-test`。本次缩小标准 100% 的基础字号，并恢复默认标准档。

## 标准字号调整

下表是应用比例 100%、系统未额外放大时的基础字阶：

| 文字层级 | 原标准 100% | 新标准 100% |
| --- | --- | --- |
| 正文、输入文字 | 16 | 14 |
| 辅助文字、标签 | 14 | 12 |
| 说明文字 | 12 | 11 |
| 页面标题 | 20 | 18 |
| 按钮文字 | 14 | 12 |

首页预览、主题标题层级与共享对话框同步采用较小字阶。字体仍为 Noto Sans SC，字重与控件最小触控尺寸沿用现有规则；系统无障碍文字缩放继续生效。

认证输入框将行高向上取整到完整逻辑像素，避免 150% 等比例下 Linux 字体度量将可见边框取成 63、外层仍为 63.5 的半像素错位；标准档 56 的最小高度与输入文字 14 保持不变。

应用默认档恢复标准（100%），85% / 100% / 115% / 130% / 145% / 160% / 175% / 190% 八档比例保持原含义。设置加载不再将 100% 强制迁移成 85%，也不在运行时额外叠加基准缩放系数。

## 升级与已保存设置

已有比例原样保留，包括 85%、100% 和较大档位；同账号重登与重启继续保留，成功切换到另一个服务器/账号时恢复标准 100%。

若安装过 1.1.49 并已保存 85%，升级后请在“我的 → 个性设置 → 显示与行为 → 应用字体大小”选择“标准（100%）”并完成，再检查新的标准字阶。旧版未记录 85% 是自动迁移还是手动选择，因此本次不批量重置已有设置。

## 构建与安装

推送测试分支后运行现有配置校验、静态分析、全量 Flutter 和后端测试，再使用仓库发布密钥生成分架构与通用 Release APK。构建缺少密钥时仍直接失败。

普通安卓手机优先使用 `arm64-v8a` APK，不确定架构时使用通用 APK；直接覆盖安装可保留已有数据。

## 实机复查

1. 在相同系统字号设置下，选择标准 100%，确认正文、任务列表、输入框、按钮、页面标题和首页预览比旧版标准 100% 更紧凑。
2. 分别切换 85%、100%、115% 及最大档，确认比例对应新的基础字阶；拖动只预览、返回取消、完成保存仍正常。
3. 保存标准 100% 后连续重启两次，并退出后登录同一账号，确认保持 100%；其他已选档位也应保持。
4. 在 320px 窄屏、系统大字号与应用最大档下，检查控件、预览、滑块和完成按钮均可访问，无文字裁切或横向溢出。

最终检查、提交、Actions 和安装包地址以交付记录为准；以上阅读体验仍需本次实机确认。
