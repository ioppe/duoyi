# v1.1.49 安卓实机测试包

版本 `1.1.49+140015`，构建分支 `fix/android-input-settings-device-test`。本次包含默认字号调整、小组件后台直接操作，以及添加到系统日历入口。

## 本次内容

- 应用默认字号改为小（85%），仍保留八档字号预览和手动选择。首次升级时，缺失或保存为旧标准档 100% 的值会一次性迁移并保存为 85%，其它已选档位保留；旧版没有显式选择标记，升级后仍可重新选择 100% 并保留。
- 小组件的完成待办、快捷打卡、开始专注通过后台回调操作，不再为这些按钮打开主界面。浏览、标题、详情、导航和“+ 添加”入口继续打开应用。后台操作先校验登录态与服务器/账号数据归属，再调用现有业务 Provider。
- Android 任务详情有截止日期时显示“添加到系统日历”：打开系统日历创建页，预填任务名、备注、日期时间和应用时区；纯日期任务预填全天事项，含具体时刻的任务预填一小时事项。用户在系统日历中点击保存后完成创建。
- 多仪不申请日历读写权限，不保存系统日历事件 ID，也不负责后续修改、删除或同步。设备没有可处理创建事项的日历应用时，提示无法打开系统日历。

## 构建与安装

测试分支推送后运行现有 GitHub Actions：配置校验、静态分析、全量 Flutter 与后端测试，然后使用仓库发布密钥生成分架构和通用 Release APK。保留签名硬校验，缺少密钥时停止构建。

普通安卓手机优先安装 `arm64-v8a` APK，不确定架构时安装通用 APK。覆盖安装以保留已有数据；升级后先打开多仪一次，再检查桌面小组件。

## 实机复查

1. 从上一版覆盖安装，确认版本显示 `1.1.49`；缺失或旧标准档 100% 应迁移为 85%，其它档位保留。迁移后连续重启两次仍为 85%；重新选择并保存 100% 后重启应保持 100%。
2. 在桌面小组件点击完成待办、快捷打卡、开始专注，确认动作生效且不弹出主界面；再打开多仪确认数据一致。点击标题或详情仍应正常进入应用，“+ 添加”仍打开任务输入表单。
3. 退出登录后点击旧小组件，确认不修改账号数据；换账号登录后确认小组件更新，旧账号内容不应写入新账号。
4. 在任务详情设置截止日期，点击“添加到系统日历”，确认日历创建页的任务名、备注、日期和全天标记正确；若任务含具体时刻，检查起止时间与时区。用户点击保存后检查系统日历中的事项。
5. 取消系统日历创建，确认不会自动创建事项；保存后在系统日历修改或删除事项，确认多仪任务仍可独立使用。设备没有可用日历应用时应显示失败提示。

本地目标测试此前 126 项通过，静态分析无诊断。最终全量检查、构建提交、Actions 和安装包地址以交付记录为准；以上系统日历兼容性和后台小组件操作仍需本次实机验证。
