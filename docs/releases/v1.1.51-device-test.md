# v1.1.51 安卓实机测试包

版本 `1.1.51+140017`，构建分支 `fix/android-input-settings-device-test`。本次将核心小组件底部导航改为组件内切页，沿用 1.1.50 的较小基础字阶和默认标准 100% 字号。

## 小组件内切换

支持待办、习惯、月历、专注的标准/简洁/详细 Provider，以及已经安装的历史兼容综合小组件。后者继续兼容，不新增概览/组合创建入口。

- 点击底部“待办 / 习惯 / 日历 / 专注”，在同一个桌面实例中切换内容与选中状态，不打开 App。
- 选择按桌面实例和实际 Provider 保存；两个实例可以停留在不同页，刷新、包更新和尺寸变化后保留各自选择，删除实例后清理状态。
- 标题、只读内容、月历“今天”和倒计时查看停留在组件内；只有空白根区域进入当前内容对应的 App 页面。
- 收起“打开 App”和“+ 添加”按钮；需要新增或编辑时，点击空白区域进入应用内对应页面。
- 首次简洁样式保持原有精简布局；已经切页的实例保留底部标签，避免切走后无法返回。

今日日程、目标、课程表、随手记、纪念日等其他独立模块的对象深链，以及 iOS 小组件行为不属于本次 Android 核心四页改动。

## 后台操作与刷新

完成待办、习惯打卡、开始专注继续使用现有后台业务链路，先校验登录态与服务器/账号 owner，再调用业务 Provider。原生切页仅修改显示状态，不直接写业务 JSON，也不改变 App 的全局导航选择。

冷后台任一种业务动作后都刷新四类核心宿主的三档 Provider 及历史兼容综合宿主，共 13 个目标。即使一个最初为习惯或综合的小组件正在显示待办，操作后也能得到新摘要，并保持当前页。

已有的主引擎动作转交、重复完成不反向取消、时区初始化、账号隔离和本地同步标记规则保持原要求。没有有效待办或可打卡习惯时，不执行后台修改。

## 构建与安装

通过现有测试分支构建；保留配置校验、静态分析、全量 Flutter/后端测试、发布密钥恢复以及分架构和通用 Release APK 门禁。缺少正式密钥时仍拒绝构建，不回退调试签名，不创建正式发布 tag，也不部署 Web 或后端。

普通安卓手机优先安装 `arm64-v8a`，不确定架构时使用通用 APK。覆盖安装后先打开应用一次以注册后台回调并刷新已有桌面实例，再返回桌面检查。

## 实机复查

1. 在现有综合小组件依次点击四个底部标签，确认内容和高亮原地变化，App 不被拉起；分别从新添加的待办/习惯/月历/专注小组件重复。
2. 点击标题、待办文字、月历“今天”和倒计时查看，确认仍留在组件内；点击空白区域才进入对应 App 页面。“打开 App”和“+ 添加”不再显示。
3. 创建两个实例停在不同页，刷新、切换主题/尺寸、重启应用后各自页签不互相覆盖；删除后新建不继承旧实例页签。
4. App 进程存活及完全退出两种情况下，跨宿主完成待办、打卡、开始专注，确认业务状态与所有相关页面摘要更新且不跳页；重复操作不反向取消。
5. 未登录或账号归属不匹配时，不修改旧账号数据；登录另一账号后只显示新账号摘要。
6. 在标准、详细及曾切页后缩小的简洁样式中检查底部标签可用、内容不溢出，窄屏与大字号下仍可操作。

本地 ADB 当前未连接设备，桌面真实点击、不同 ROM 与 launcher 排版仍需本次真机检查。自动检查、最终提交、Actions 与安装包地址以交付记录为准。
