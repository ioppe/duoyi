# Web 通知授权与网页提醒

Web 使用浏览器 Notifications 权限。通过 HTTPS 或 localhost 打开应用，在任务详情、习惯详情或目标编辑的提醒健康提示中点击「通知授权」，才会发起权限请求；启动、自动健康检查和返回页面时只读取状态。

允许后，页面显示浏览器通知已授权。拒绝、关闭权限框、浏览器不支持、非安全上下文和调用失败分别给出反馈；请求在途时防止重复点击。浏览器已拒绝的权限通常不能由页面再次弹框改变，应从地址栏的站点信息或网站设置中允许「通知」，再返回应用刷新状态。应用不会替用户修改浏览器或系统设置。

网页打开且具备权限时，可发送普通浏览器通知，并在当前页面中调度提醒。同一通知编号替换旧计划，取消、取消全部及账号清理使旧计划失效；初始化、自动刷新与后台调度不主动申请权限。较远未来的提醒按不超过一天的间隔分段等待，每次唤醒复核到期时间，避免浏览器长计时溢出而提前显示。具体是否显示横幅或声音，仍由浏览器及系统通知设置决定。

投递优先使用浏览器 Notification 构造器；构造器调用失败时，在 2 秒内查找现有且已激活的 ServiceWorkerRegistration，通过其 showNotification 投递，不注册新的 Service Worker。两条路径都不可用或投递失败时返回错误。投递等待超时会返回失败，但不能撤回浏览器底层尚未完成的投递；迟到成功仍会被跟踪，若对应计划已取消或账号已退出则关闭该通知。构造器路径可将点击接回当前页面；Service Worker 路径的点击由浏览器及现有 Worker 处理，不保证唤起应用。取消操作只关闭当前页面跟踪过的通知编号及注册；刷新页面后不会尝试关闭未知通知。

浏览器可能限制后台计时，网页休眠或后台节流会使提醒延迟。关闭网页、退出浏览器或设备睡眠后，页面内定时提醒不能保证触发。需要可靠后台提醒时使用原生客户端。本实现没有新增服务端 Web Push、推送订阅、后台唤醒服务或原生精准闹钟能力。

实现通过条件导出选择 Web 通知适配，Android、iOS、macOS、Linux 与 Windows 继续使用原有原生通知实现。Web 权限状态和请求结果可独立测试；真实浏览器验收时需分别记录用户点击调用、API 结果、页面反馈，以及浏览器原生权限框和系统横幅的实际测试范围，不把受控 API 结果称为真实系统授权操作。

人工回归步骤见 [手工回归清单](manual-regression-checklist.md) 的「通知 vs 闹钟」。通知授权不改变任务的截止日期、进入日期、账号数据或服务器通知配置。
