# 统一账号入口

Web 与 Android 共用 `LoginScreen`、`AuthPageFrame` 和认证方式选择器。桌面采用产品说明与表单双栏，手机采用单列表单；使用应用主题、资源圆体和共享表单尺寸。密码登录为默认方式；Web 不提供令牌登录，安装客户端在同一张卡片内切换密码和令牌。邮箱验证码方式由服务器能力控制。

登录与注册共享同一张卡片的尺寸与纵轴翻转。卡片内部不使用纵向滚动区：常规宽度的邮箱/邀请码注册将密码和确认密码并排，窄屏或放大文字时改为纵向；两面根据同一注册策略和文字比例共同确定高度。默认 Web 手机460px、桌面484px，安装客户端为服务器地址预留一行。所有必填项与主操作完整显示，提示信息有独立高度；屏幕或键盘空间不足时只滚动整页。主操作置于卡片底部，“忘记密码”和注册切换位于按钮下方同一行。减少动画设置下直接切换，翻转时只挂载一份表单。

Web 的用户功能与管理功能使用同一个应用、同一个登录入口。首次安装的 `admin` 是初始管理员账号，其他账号按服务器实际角色显示；普通注册不会获得管理权限。登录后进入今日页，通过“我的 → 设置 → 管理员后台”使用授权的管理功能，无须另行登录。

## Web 会话

`WebAuthGate` 位于 `MaterialApp.builder`，包住整个应用 Navigator。未登录时仅挂载公开的登录路由，个人页面不会先构建再被覆盖。恢复会话先向 `/api/auth/me` 验证账号和角色，成功后才挂载应用。返回的账号必须与保存的身份一致，管理权限不沿用未验证的缓存值。

退出登录、会话过期或账号变化会移除原应用路由栈；登录其他账号会从新路由开始。验证时断网保留本地会话但阻止进入，提供重试或重新登录。入口验证被后台资料刷新替代时重新请求一次，连续被替代仍不放行。强制更新要求继续优先于应用内容。

“我的”显示当前账号的昵称或用户名，不再提供登录按钮；保留退出登录。管理入口同时要求已登录和管理员角色，后端接口继续验证管理权限。安卓既有离线使用方式保留，可从个人资料进入同样风格的登录页。

## 首次安装

没有既有表结构的新数据库自动创建默认 `admin`。未配置显式密码时使用系统安全随机源生成密码，仅在数据库实际路径旁保存 `<DUOYI_DB_PATH>.bootstrap-admin.json`，权限 `0600`。运维人员在服务器本地读取后，通过普通密码表单登录。密码不出现在公开 API 或日志。

已有安装不会重建、重置或提升账号，不改变密码盐、数据或角色。初始凭据文件不随密码变更更新，也不会在删除后重新生成。完整运维说明见 [configuration.md](configuration.md)。

登录页不判断访问者是否首次使用，也不展示固定的首次管理员提示。首次安装凭据获取仅在安装说明中提供。

## 注册与连接

Web 固定使用当前站点；Android 保留运行时服务器地址与令牌连接。注册开放状态、邮箱验证和邀请码仍由各服务器策略决定，登录页读取当前服务器配置。更换服务器后注册前重新读取策略；账号、令牌及本地数据继续按服务器和账号隔离。

新安装默认用用户名和密码注册，页面只要求用户名、密码及确认密码；不再提供昵称输入，初始昵称使用用户名，登录后在“我的 → 个人资料”修改。默认不要求邮箱，未配置邮件服务时也不显示可选邮箱绑定。邮件可用时可由用户选择绑定，只有管理员明确启用的邮箱验证策略才会强制验证。已有数据库保存的注册策略保留，重启不再自动把邮箱验证改为开启。

邮箱验证码登录默认关闭。管理员先在“全站设置 → 账户、注册与用户组”打开“允许邮箱验证码登录”，再在邮件设置中启用邮件服务、配置当前发信渠道。公开 `/api/config` 只返回最终可用状态 `email_code_login_enabled`，不会返回发信账号或密钥。关闭开关、停用邮件服务或缺少当前渠道配置时，前端隐藏该方式，服务端同时拒绝登录用途的发码和验证码登录请求。绑定邮箱、注册验证与找回密码继续采用各自原有策略。

## 验证

行为测试覆盖登录前不挂载私人页面、恢复/过期/断网会话、后台刷新竞态、退出时移除深层路由、普通及邮箱注册、发码和重复提交、密码可见性、找回密码、九主题、窄屏/字体缩放/键盘布局，以及卡片内部无纵向滚动和字段不被底部操作遮挡。实际构建截图与运行结果见 [无内部滚动的认证卡片](../evidence/screenshots/auth-static-form/README.md)。
