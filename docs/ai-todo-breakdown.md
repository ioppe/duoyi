# AI 拆解与任务创建

今日页、待办页和四象限复用同一新建表单。点击“AI智能拆解”只填写草稿，最终通过“添加任务”统一保存，不会提前写入任务。

## 自动填写

- 子任务：结构化生成具体动作，清理空白、列表编号和重复项，最多保留七条，保存为具有独立ID和顺序的子任务。
- 清单：只使用表单已有且可编辑的清单名称；不会新建AI臆造的清单，也不会跳过共享空间权限检查。
- 优先级：填写Q1–Q4四象限，沿用应用的主题名称。独立的低/中/高/紧急标记仍不参与新建任务，存储值为`TodoPriority.none`。
- 提醒：识别到明确、有效的未来时分时自动开启“到点提醒”；只有日期不补默认9点，过去的一次性时间不自动开启提醒。
- 用户手动改过的清单、四象限和提醒保留。等待AI时改变任务文字、应用时区或账号连接，会丢弃旧结果；关闭弹窗后不会写入任务。AI处理中不能抢先保存不完整的草稿。
- 明确的本地时间解析优先于AI日期建议；本地无法识别时才采用通过校验的AI日期。坏JSON或没有可用子任务会显示失败，原输入保留。

## 日期与时区

日期预览会标明当前应用IANA时区。默认跟随系统，也可在应用设置固定时区。

“后天下午3点”表示应用时区里后天的15:00，不会先按设备时区解析再换算。例如同一瞬间`2026-10-21T02:00Z`，上海是21日，纽约仍是20日，因此“后天”在两地分别为23日和22日。

完整ISO时间戳支持明确瞬间：`2026-10-23T02:30:00Z`在上海显示23日10:30；不带offset的ISO时间按应用时区解释。AI返回的Z/数值offset也转换到应用时区。任意自然语言城市名或时区缩写不保证可由本地解析器识别，应检查预览。

只有日期的值保持floating日历日期，不做跨时区平移，也不因午夜夏令时跳时丢弃。预览、自动提醒和保存共用经过重复规则、同分钟顺延处理的有效草稿；进入新一天或应用时区变化时不会悄悄使用另一份未展示的日期结果。纽约回拨重复的时段保留明确offset指定的瞬间。提醒序列化为UTC后，重新调度先恢复应用时区日期，再应用规则，避免凌晨提醒提前一天。

## 提醒渠道

安装客户端继续在保存前检查通知权限和有效时间。新建时关闭提醒，会同时清除新计划、旧兼容开关与旧提醒时刻。

当前Web本地系统通知是占位实现。因此Web会保存提醒配置并明确提示本地系统通知未注册；可在安装客户端同步后使用。保存配置不等同于已验证手机后台或锁屏通知到达。
