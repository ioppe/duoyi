# Web 通知授权与 macOS 跨屏拖动修复

本目录记录从 `8ac46df27841c2eb3ff5e05be66a581e3bc53088` 开始的两项修复。验证前已安全整合并行提交 `22bf3550524b347a425ae65e7d3be73503c49adb` 的 macOS 待办顶部筛选，保留此前紧凑悬浮窗、字形居中和透明图标。版本仍为 `1.1.47+140013`；原始工作区只读，修改发生在隔离构建仓库。

## 修复内容

Web 原先条件导出空通知实现，授权固定返回 false，点击后没有反馈。现使用浏览器 Notifications API，用户点击时在首次 await 前同步发起请求，保留 user activation。允许、拒绝、未选择、调用失败、不支持、非安全上下文与在途状态分别反馈。已拒绝时给出地址栏站点设置说明；启动、刷新与调度只读取权限，不自动弹框。说明文字可换行，窄屏不会只显示一行省略号。

通知优先使用构造器；构造器抛错时有界获取现有且已激活的 ServiceWorkerRegistration 投递，不注册新的 Worker。账号清理与取消统一使旧排期和在途交付失效。远期提醒使用有界分段等待，到期后才投递。网页关闭后不保证提醒，后台节流也可能延迟；没有新增 Web Push 后端或后台唤醒能力。

macOS 基线方法探针确认 AppKit 的默认窗口约束会拉回上沿候选位置，不同尺寸及错位屏幕会暴露这种边界处理问题。修复保留原生 performDrag，放行跨屏建议 frame，统一使用全局逻辑点。拖动中的真实尺寸变化即时应用并保持实际 origin；松手时，完全被可用屏幕并集覆盖的卡片保持位置，屏外卡片才回收至可达区域。计时、记录和主题仍由原有主引擎与 Provider 管理，普通 tick 不移窗。

## macOS 原生检查

[原生记录](native-validation.json)和 [76 项检查明细](native/native-smoke.json)覆盖生产 AppKit 面板、合成显示器几何、拖动生命周期、松手恢复、尺寸变化、主题、字形与紧凑控件。相同的 18 个直接方法探针位置，基线有 6 个被默认约束改写，修复后 18 个均保持建议 frame。`native/` 内有 8 张真实 NSView 渲染图，使用从 Flutter 导出的主题与 Noto Sans SC，最大可见文字居中偏差为 0.25pt。

本机观察到两块尺寸不同、含负坐标与上沿错位的显示器，两者缩放均为 2×。本轮没有注入真实鼠标跨屏，没有实测混合缩放，也没有在本机编译或安装完整 Flutter macOS 应用。这些检查与 CI 完整构建分别记账；macOS CI 包仍是 universal unsigned/unnotarized，不代表签名、公证或 Gatekeeper 验证通过。

## 浏览器检查

[浏览器记录](browser-validation.json)包含 9 个去重后的场景与 22 张截图：首轮 r3 包完成 8 组检查、16 张截图；最终 r5 包复测授权入口、390px 已授权说明和 Service Worker 回退，并增加超时后退出账号的迟到清理回归，新增 6 张截图。复测项按相同场景编号更新结果，不累加为新场景；每项保留实际使用的包哈希。最终清理回归中，迟到投递的 tag 被关闭，剩余通知数为 0。

测试只使用 loopback 夹具和可丢弃账号。真实 API 请求保留用户激活，但无头浏览器自动拒绝，没有操作原生权限气泡；受控允许或 API 接收不等于系统授权框、横幅可见。截图已逐文件核对尺寸与 SHA，并检查窄屏说明。未观察到通知相关未处理错误；启动及账号清理的既有插件日志如实保留。另记录通用测试通知界面的既有提示问题：发送异常被 Provider 捕获后，页面仍可能显示“测试通知已发送”；相关两处源码与本轮 HEAD 相同，本轮没有改动该通用提示逻辑。
