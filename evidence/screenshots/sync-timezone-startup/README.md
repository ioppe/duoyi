# 同步时间时区与今日待办冷启动修复

## 实现与自动检查

同步卡片只在显示处调用 `AppClock.toLocal`，通过 `AppClockScope` 订阅时区变化；不改全局日期格式化器，避免平移浮动日期。UTC 与纽约两种宿主时区分别通过 25 项卡片测试，包含生产无 `Z` 本地 ISO 格式、同挂载树切区、跨日、纽约冬夏令时、加德满都非整小时偏移，以及时间存储与请求次数保持不变。

待办初始读取在首帧后独立启动，实际读取的整个生命周期处于脏标记抑制范围，公开配置请求仍立即发起。普通读取、强制重读与本地写入共用队列；大缓存解码、损坏备份和修复写入处核对存储快照，避免读取期间收到的新云端数据被旧缓存反写。持续替换超过重试上限会让读取及等待它的编辑失败，存储稳定后可重试。其他模块保留 14 秒、75 秒与 12 秒间隔的错峰。

最终定向检查为 **14 个测试文件 / 161 项通过**；完整 Flutter 套件为 **348 个测试文件 / 2448 项通过**，失败、错误、跳过均为 0。全仓 `dart analyze --fatal-infos`、六文件格式和 `git diff --check` 均通过。测试后与构建后六文件 SHA 一致。Release Web 的 **409 个输入**前后稳定，运行文件 **120 个 / 107,541,481 字节**；版本保持 `1.1.47+140013`，Logo、favicon、字体与授权文件检查通过。

## 验证边界

真实设置界面的纽约/上海切换因可用自动化控件未能打开选择器而记为 **NOT RUN**；同一卡片的即时切区与存储不变由 widget 测试覆盖，不计作浏览器通过。旧包卡片时间未拍到，因此上海卡片结果是新包阳性验证，不冒充已完成的旧/新卡片视觉对照。

跨构建的 CLI 状态文件恢复未建立：首次加载只能观察到四个键，没有应用启动前的存储快照，无法确定是状态导入还是应用启动过程导致。后续使用真实登录表单，并在同一最终构建内正常刷新，登录、任务与偏好持续保留；该结果覆盖缓存冷刷新，不等于原生覆盖安装验证。应用时区和自动同步偏好为应用自身持久化键预置，已明确记录为非设置 UI 操作，未修改系统时区。

夹具只提供可丢弃账号与固定远端快照，记录但不应用客户端上传，AI 关闭；不用于证明编辑/LWW。`pageerrors=[]`，但 console 仍有既有账号清理 null-check、Web 插件未实现及闹钟清理日志。未进行生产登录、真实模型调用、原生安装、签名、公证或 Gatekeeper 验证。
