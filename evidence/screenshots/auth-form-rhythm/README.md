# 认证卡片的连续排版与统一输入框

查看 [实际页面与同尺寸对比](index.html)，或直接查看 [登录对比](09-login-comparison.png) / [注册对比](10-register-comparison.png)。图像均来自实际 Flutter 构建或真实字体组件渲染。

## 设计与实现

沿用多仪已有的资源圆体700与品牌主题，保留主题切换、480ms双向翻转和等高卡片。默认主题的页面灰`#F6F7F9`、表面白`#FFFFFF`、正文`#1F2933`、次级文字`#667085`、边框`#D9E0E8`、主色`#C85656`继续由现有主题提供，没有引入另一套配色或字体。

内容采用左对齐的连续顺序：标题和说明 → 登录方式 → 输入项 → 主操作 → 辅助操作。短表单作为完整内容组在共享卡片内居中。注册策略需要更多字段时，两面仍共用同一高度；卡片内部无纵向滚动，键盘或视口不足时只滚动外层页面。

- 字段间距统一16px，末项到主按钮24px，移除字段与固定底部按钮之间的弹性空白。
- 认证页专用`AuthFormFieldTheme`统一约束、底色、边框、16px内边距和标准密度；常规输入框可见高度56px，1.5倍字体68px，2倍字体80px。
- 密码与无图标的确认密码使用相同可见高度；空间不足时仍改为纵向排列。
- 邮箱验证码继承同一认证主题；发送按钮与验证码框等高，使用同一输入控件圆角。
- 默认不使用邮箱注册、昵称使用用户名、服务器邮箱策略、角色与账号隔离保持原有行为。

## 问题复现与修正

第一组5个新增回归在旧版全部失败：默认密码框到按钮58px，强制邮箱策略下130px；邮箱到验证码只有8px，与其他字段的16px不一致。

实际截图进一步发现，单测只测`TextField`外层56px会漏掉确认密码的可见边框只有48px。原因是桌面紧凑密度使无图标输入容器缩短8px，图标又将其他框撑高。加强后的测试通过`InputDecorator.containerOf`测量真正绘制边框的容器，并在标准/紧凑密度和1/1.5/2倍字体下验证空白、聚焦和已填写状态。修正前紧凑密度的三个用例分别复现48/60/72px；认证主题指定标准密度后，均与56/68/80px的共同高度一致。

原有两条旧断言随布局契约更新：发送动作从固定56px改为共享缩放高度，令牌/密码方法从固定绝对纵坐标改为共同尺寸及16px行距。选择器字体、卡片等高、发码冷却、防重复提交和账号隔离检查保留。

## 验证结果

- 最终177项认证、资料、门禁、服务器隔离、字体与布局相关测试通过，包括九品牌、320px、放大字体、英文、键盘与减少动画回归。
- 真实字体Android平台组件渲染1项通过，覆盖浅色、深色、默认注册、邮箱注册和2倍字体。
- `flutter analyze --no-pub`、Web release构建、所改Dart文件格式检查与`git diff --check`通过。
- 隔离服务开启邮箱策略，以本地文件捕获验证码，实际完成发码、邮箱注册及普通账号验证；随后关闭邮箱策略检查默认三字段注册，再使用新账号完成真实密码登录。浏览器无错误。没有发送外部邮件。
- 本次没有修改后端，也没有重跑完整Flutter套件、后端套件或APK构建。

验证结束后关闭测试浏览器，停止临时服务并删除临时数据库、账号凭据与验证码。证据不含密码、令牌或有效验证码。未部署生产环境。
